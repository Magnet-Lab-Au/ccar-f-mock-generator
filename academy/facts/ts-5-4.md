## 2. The takeaway

**Proposed heading (9 words):** "Keep findings in files, keep exploration in subagents"

**Short answer:** A long exploration fills the context, and then the answers get worse. Send verbose searches to subagents that return summaries, write the key findings to files on disk, and compact or resume from those files, not from the old conversation.

Support: F1 to F3 (K1), F4 to F6 (K2, S2), F7 to F10 (K3, S1), F11, F12 (S3), F13, F14 (K4, S4), F15 to F18 (S5).

## 5. Beyond the exam

1. **Know what survives compaction.** Condition: Claude Code. CW 1605: "| Files Claude read or edited | Claude Code re-reads up to five, most recently modified first |". CW 1613: "Path-scoped rules and nested CLAUDE.md files load into message history when Claude reads, writes, or edits their trigger file, so compaction summarizes them away with everything else." So a finding that is only in the conversation is at risk. A finding in a file that loads from disk is not (F6).
2. **Tell the compactor what to keep.** HCW 140: "To control what's preserved during compaction, add a "Compact Instructions" section to CLAUDE.md or run `/compact` with a focus (like `/compact focus on the API changes`)." In the Agent SDK, LOOP 277: "* **`PreCompact` hook:** Run custom logic before compaction occurs, for example to archive the full transcript." Marked: the guide names only `/compact` (S5).
3. **Use memory files and compaction together.** Condition: Claude API. MT 985: "For long-running agents, consider using both: compaction keeps the active context small without client-side bookkeeping, and memory preserves the information that must survive summarization." Marked: the guide says "scratchpad files". The documentation says "memory files" (C2).
