## 2. The takeaway

**Proposed heading (9 words):** "Batch only the work that can wait a day"

**Short answer:** The Message Batches API costs half, but a batch can take up to 24 hours with no promised time, so use it only for work that nobody waits for. Match each result to its request by `custom_id`, and send again only the requests that failed.

Support: F1 to F5 (K1, K2, S1), F9 to F11 (K4), F12 to F15 (S3), F6 to F8 (K3).

## 7. Code for a popup

Read the results and sort each failure by its `custom_id`. Condition: the Python SDK. BATCH 756-774 (exact, without the fence lines and the indent of 2 spaces):

```python
client = anthropic.Anthropic()

# Stream results file in memory-efficient chunks, processing one at a time
for result in client.messages.batches.results(
    "msgbatch_01HkcTjaV5uDC8jWR4ZsDV8d",
):
    outcome = result.result
    match outcome.type:
        case "succeeded":
            print(f"Success! {result.custom_id}")
        case "errored":
            if outcome.error.error.type == "invalid_request_error":
                # Request body must be fixed before re-sending request
                print(f"Validation error {result.custom_id}")
            else:
                # Request can be retried directly
                print(f"Server error {result.custom_id}")
        case "expired":
            print(f"Request expired {result.custom_id}")
```

## 9. Conflicts

- **C1. K3 and server tools.** K3 (GUIDE 511) and GUIDE 1007 say that batches have no multi-turn tool calling. BATCH 55-60 lists tool use, with all server tools, under "What can be batched". BATCH 1567 (F8): a batch request runs the server-side agentic loop. So K3 holds for client tools only (TUO 141, F6). The exam uses the guide. Read K3 as "your own tools".
- **C2. "Multi-turn".** BATCH 62 lists "Multi-turn conversations" under what can be batched: earlier turns in one request. K3 means a tool loop inside one request. A possible confusion.
- **C3. S2 says "guarantee".** BATCH 47 says that under load "you may see more requests expiring after 24 hours", and BATCH 1849 says that a batch can expire. An expired request needs a new batch, so no submission plan can guarantee a 30-hour SLA. The exam uses the guide's arithmetic. A weak claim, not a direct disagreement.
- **C4. S4 has weak documentation support.** BATCH 1819 and 424-425 say: test the request shape, to avoid validation errors. They say nothing about prompt quality on a sample. DTS 10 shows prompt work as a cycle (figure text: "test cases, preliminary prompt, iterative testing and refinement, final validation, ship"), not for batches. The claim rests on the guide.
