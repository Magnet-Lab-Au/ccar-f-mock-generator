## 2. The takeaway

**Proposed heading (8 words):** "A schema guarantees the form, not the values"

**Short answer:** Give Claude a JSON schema, as a tool that `tool_choice` makes Claude call, and the output always parses. Code must still check the values, and a field that a source can lack must be nullable, so that Claude does not invent a value.

Support: F1 to F4 (the form), F8 to F10 (`tool_choice`), F13 and GUIDE 474 (the values), GUIDE 482 and F15 (nullable). Condition: on the newest models a forced `tool_choice` returns an error, and the documentation names structured outputs as the replacement (F11, C2).

## 9. Conflicts

- **C1. "Tool use" as the guarantee.** K1 (GUIDE 472) says tool use with JSON schemas gives guaranteed output. The documentation gives the guarantee only with `strict: true` (ST 7) or with structured outputs (SO 54). Without strict mode, a tool input can miss required fields (ST 18). Even then, SO 2708 says "in most cases". GUIDE 1008 names "strict mode for syntax error elimination", so the guide knows strict mode, but K1 does not name it. The exam uses the guide.
- **C2. Forced `tool_choice` on current models.** S2 and S3 (GUIDE 480, 481) and K2 (473) teach `any` and a forced tool. DT 564 says these return a 400 error on Claude Opus 5.5, Claude Sonnet 5.5, Claude Fable 5.1 and Claude Mythos 5.1, and DT 563 says they fail with manual extended thinking. The mock builder follows the documentation (decision 0040). The exam uses the guide.
- **C3. Semantic errors.** K3 (GUIDE 474) has no sentence in the documentation. SO 58 and SO 2636 support it only in part. The claim rests on the guide.
- **C4. No documentation for S5 and S6.** No page read names an "other" + detail field, an "unclear" value, or normalization rules in the prompt. The claims rest on the guide.
- **C5. Optional fields.** S4 (GUIDE 482) makes fields nullable against fabrication. SO 2772 says "Make parameters `required` where possible." and counts each optional field against a limit of 24 (SO 2753). The two do not exclude each other: a required field can have the type `["string", "null"]` (SO 2754), but that counts against the limit of 16 union types. The exam uses the guide.
- **C6. Records of the mock builder.** Decision 0040 line 6 says that the diagrams of steps 2, 4 and 6 show the deviation. Diagram 08 (step 6) and diagram 07 (step 5) have no text "structured outputs", "output_config" or "4.3". Diagram 06 (step 4) lists S5 only, but the build guide of step 4 lists S5, K1 and S3.
- **C7. The page changed after decision 0040.** Decision 0040 line 53 quotes DT7: "(Claude Opus 5 supports it with thinking on)". DT 563 now says "(models with thinking on by default, such as Claude Opus 5 and Claude Haiku 5.5, accept it, but a forced call skips thinking: the response starts with the tool call and has no `thinking` block)". DT 866 is new. The decision stays correct. SO and SO7 differ in one line (SO 26, `claude-haiku-5-5` in the model list), so line numbers after line 25 differ by 1. The card `s3-docs` cites SO7 line 2637 (SO 2638), and says that the live page agreed.
