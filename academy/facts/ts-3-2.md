## 2. The takeaway

**Proposed heading (10 words):** "Share skills through the repository and tune them with frontmatter"

**Short answer:** A command or skill in the project's `.claude/` folder reaches the team through git, and one in `~/.claude/` stays personal. Frontmatter sets how a skill runs (`context: fork` runs it in its own subagent), and unlike CLAUDE.md, a skill loads only when it is used.

Support: F1 to F6 (scope), F7 to F22 (frontmatter), F23 to F26 (skill against CLAUDE.md). "tune" is weak for `allowed-tools` and `argument-hint` (C1, C2).

## 5. Beyond the exam

1. **Commands are now skills.** SK 16: "**Custom commands have been merged into skills.**" With the same name, the skill wins (SK 209). Marked: the guide uses `.claude/commands/` (K1, S1, question 4). The documentation calls it "the older format" (SK 172) (C3).
2. **`allowed-tools` is a grant, not a fence, and a repository can grant itself tools.** SK 600: "It does not restrict which tools are available". SK 602: "Workspace trust doesn't gate this field. Claude Code applies a project skill's `allowed-tools` even in a `-p` run in a folder you've never trusted." To restrict, use `disallowed-tools` (SK 408) or deny rules (SK 615). Marked: S3 says the opposite (C1).
3. **Stop Claude from starting a skill with side effects.** SK 542: "**`disable-model-invocation: true`**: Claude can't invoke the skill on its own. Use this for workflows with side effects or that you want to control timing, like `/commit`, `/deploy`, or `/send-slack-message`." The guide does not name this field.

Condition: on a claude.ai upload or the Skills API, `argument-hint` is an error. SK 435: "Unexpected key(s) in SKILL.md frontmatter: argument-hint."
