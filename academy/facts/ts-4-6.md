## 2. The takeaway

**Proposed heading (10 words):** "A new instance reviews each file, then the files together"

**Short answer:** The session that wrote the work keeps its reasoning, so it seldom questions its own choices. Give the review to a new instance that sees only the work and the criteria, split a large review into one pass for each file plus one pass across the files, and route the findings by a confidence that is calibrated.

Support: F1 to F4 (K1, K2, S1), F9 to F11 (K3, S2), F13 to F16 (S3).

## 5. Beyond the exam

1. **A fork is not an independent reviewer.** SA 1158: "This drops the input isolation that subagents otherwise provide: a fork sees the same system prompt, tools, model, and message history as the main session, so you can hand it a side task without re-explaining the situation." Condition: Claude Code subagents. A reviewer is only as independent as its input.
2. **A reviewer finds gaps because you asked it to.** BP 549: "A reviewer prompted to find gaps will usually report some, even when the work is sound, because that is what it was asked to do." The guide does not name this cost.
3. **Claude Code has built-in multi-instance review.** CR 33 (F13) and UR 17: "* **Higher signal**: every reported finding is independently reproduced and verified, so the results focus on real bugs rather than style suggestions". The guide names neither product. Marked: C5.

## 9. Conflicts

- **C1. S3 and the guide's own warning.** S3 (GUIDE 535) teaches self-reported confidence for routing. 5.2-K3 (GUIDE 566) says "self-reported confidence scores are unreliable proxies for actual case complexity", and GUIDE 776 agrees (F17). The guide resolves it with calibration on labeled sets (GUIDE 622). The exam uses both: calibrated confidence routes review, raw confidence does not decide escalation. Decision 0019 lines 22-23 record this.
- **C2. "Extended thinking" in K2.** ET 12 says extended thinking is deprecated on the 4.6 models and rejected from Claude 4.7. The exam uses the guide term. Read it as "more reasoning in the same instance".
- **C3. Claude Opus 5 and verification subagents.** OP5 61 says to remove "use a subagent to verify" from prompts. OP5 74: "do not use subagents to verify or double-check your own work." Condition: Claude Opus 5, for cost. BP 536 recommends an independent reviewer. The exam uses the guide (S1).
- **C4. Self-check instructions.** PBP 782: "This catches errors reliably, especially for coding and math." K2 says an independent instance is more effective than "self-review instructions". K2 compares, so this is a weak claim, not a contradiction: no documentation states the comparison.
- **C5. The axis of the split.** K3 splits by file (GUIDE 529). CR 33 splits by "a different class of issue". WF 270 splits by file. Both are multi-pass. A possible confusion.
- **C6. Voting runs.** RH 59: "Run Claude through the same prompt multiple times and compare the outputs." Question 12 calls a 2-of-3 vote wrong (F12). RH detects hallucination, the vote filters findings. A possible confusion.
- **C7. The same ideas in three task statements.** 4.6-K3 and 4.6-S2 repeat 1.6-K2 and 1.6-S2 (GUIDE 201, 207). 4.6-K1 repeats 3.6-K4 (GUIDE 420). Question 12 fits 1.6 and 4.6.

Decision 0032 line 190 lists 4.6-S3, which the build does not use. Also, SG 9 says "review its own code changes", but SG 112 says a separate call reviews (wording only).
