## 2. The takeaway

**Proposed heading (9 words):** "A subagent knows only what the coordinator passes it"

**Short answer:** A coordinator starts each subagent with a call of the Task tool. The subagent does not see the conversation of the coordinator, so the coordinator puts the complete findings and their sources in the prompt, and it sends parallel calls in one response.

Support: facts F1, F3, F5, F9 and F11 below. The documentation now names the tool "Agent" (conflict C1), and a subagent also loads the project CLAUDE.md (conflict C3). The heading is true for the conversation, which is what the guide tests.

## 7. Code for a popup

SDK-SUB 43-91 (Python, exact). It shows `allowed_tools` with "Agent", and two AgentDefinitions with `description`, `prompt` and `tools`.

```python
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition


async def main():
    async for message in query(
        prompt="Review the authentication module for security issues",
        options=ClaudeAgentOptions(
            # Auto-approve these tools
            allowed_tools=["Read", "Grep", "Glob", "Agent"],
            agents={
                "code-reviewer": AgentDefinition(
                    # description tells Claude when to use this subagent
                    description="Expert code review specialist. Use for quality, security, and maintainability reviews.",
                    # prompt defines the subagent's behavior and expertise
                    prompt="""You are a code review specialist with expertise in security, performance, and best practices.

When reviewing code:
- Identify security vulnerabilities
- Check for performance issues
- Verify adherence to coding standards
- Suggest specific improvements

Be thorough but concise in your feedback.""",
                    # tools restricts what the subagent can do (read-only here)
                    tools=["Read", "Grep", "Glob"],
                    # model overrides the default model for this subagent
                    model="sonnet",
                ),
                "test-runner": AgentDefinition(
                    description="Runs and analyzes test suites. Use for test execution and coverage analysis.",
                    prompt="""You are a test execution specialist. Run tests and provide clear analysis of results.

Focus on:
- Running test commands
- Analyzing test output
- Identifying failing tests
- Suggesting fixes for failures""",
                    # Bash access lets this subagent run test commands
                    tools=["Bash", "Read", "Grep"],
                ),
            },
        ),
    ):
        if hasattr(message, "result"):
            print(message.result)


asyncio.run(main())
```

## 9. Conflicts

- **C1. The name of the tool.** GUIDE 152: "The Task tool". CC-SUB 490: "In version 2.1.63, the Task tool was renamed to Agent. Existing `Task(...)` references in settings and agent definitions still work as aliases." SDK-SUB 307: still "Task" in the `system:init` tools list. The exam uses "Task". Show both (decision 0014). Same as C3.3 in `academy/facts/claude-code.md`.
- **C2. "allowedTools must include Task".** GUIDE 152 says it is a requirement. The documentation says that `allowed_tools` only approves (SDK-PERM 76, 80) and that the Agent tool needs no approval: SDK-PERM 108: "Calls that need no approval in `default` mode run whether or not you list them, such as ... tools like `Agent` that don't ask before running". So in the current product the list is not a requirement. The examples still list "Agent" (SDK-SUB 52). The exam uses the guide. Older SDK versions: not checked.
- **C3. "Explicitly provided in the prompt".** GUIDE 153 agrees with SDK-SUB 178 for the conversation. But a non-fork subagent also gets the project CLAUDE.md and tool definitions (SDK-SUB 189-190), and a fork subagent gets the full conversation (CC-SUB 1158). The exam uses the guide. Same as C3.4 in `academy/facts/claude-code.md`.
- **C4. Which fork.** GUIDE 155 says "Fork-based session management". The documentation has a session fork (`fork_session`, SDK-SES 290) and a fork subagent (CC-SUB 1158). The exam line GUIDE 1014 names `fork_session`. K4 overlaps with 1.7 (GUIDE 215, 222).
- **C5. "Rather than across separate turns".** GUIDE 161. SDK-SUB 164: "Subagents run in the background by default." So subagents that start in separate turns can also run at the same time. The rule of the guide is still true for the time to start all of them. Weak claim, note only. Also: PAR 11 says that the client chooses the order of execution, and SDK-LOOP 186 says which tools run concurrently, but it does not name the Agent tool (not found).
- **C6. Weak support for S4.** PBP 779 is about thinking, not about coordinator prompts. PBP 902 (success criteria) fits better. No documentation sentence says "goals and quality criteria rather than procedural steps" for a coordinator.
- **C7. Weak link for step 0.** Step 0 uses 1.3-S2 for records with IDs. No agent passes context in step 0 (decision 0026, line 10). A page must not say that the build passes context between agents.

Number of conflicts: 7 (C1 to C4 are disagreements of sources, C5 to C7 are weak claims).
