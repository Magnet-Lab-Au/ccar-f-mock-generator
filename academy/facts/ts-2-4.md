## 2. The takeaway

**Proposed heading (9 words):** "Share MCP servers in .mcp.json, with secrets in variables"

**Short answer:** A team commits shared servers in `.mcp.json` and writes each token as `${VAR}`, and a person keeps private servers in `~/.claude.json`. The agent gets the tools of all servers together, and resources show it what data exists before it searches.

Support: F1 to F4 (scopes and file), F6 to F8 (expansion), F9 to F11 (all servers together, with condition C3), F12 to F14 (resources), F15 and F17 (descriptions, existing servers).

## 5. Beyond the exam

1. **A project server needs approval, except where no prompt can show.** CC-MCP 592: "For security reasons, Claude Code prompts for approval in interactive sessions before using project-scoped servers from `.mcp.json` files." CC-MCP 594: "In `claude -p` runs, [Agent SDK](/docs/en/headless) sessions, and [cloud sessions](/docs/en/claude-code-on-the-web), Claude Code can't show that prompt: it loads project-scoped servers without asking." Marked: the guide says nothing about approval or trust of a committed `.mcp.json`.
2. **Some credential names never expand toward a remote server.** CC-MCP 670: "In a remote server's `url` and `headers`, Claude Code reads credential variables from your environment as empty rather than expanding them." A name of your own, such as `API_KEY`, expands (CC-MCP 680). Condition: remote servers, `url` and `headers` only. Marked: the guide example `${GITHUB_TOKEN}` (GUIDE 291) is not in the list that the page gives. Not checked whether the full covered set includes it.
3. **A configured server is not a permitted server (Agent SDK).** SDK-MCP 181: "MCP tools require explicit permission before Claude can use them. Without permission, Claude will see that tools are available but won't be able to call them." The fix is `allowedTools` with a wildcard such as `"mcp__github__*"` (SDK-MCP 199). Marked: K3 says the tools are "available simultaneously" (GUIDE 292) and names no permission step.

## 9. Conflicts

- **C1. Two scopes or three, and where "experimental" goes.** K1 and S2 put "personal/experimental" servers at "user-level (~/.claude.json)" (GUIDE 290, 298). The documentation has three scopes (CC-MCP 529). It names local scope, the default, for "experimental configurations" (CC-MCP 539), and user scope for servers "across different projects" (CC-MCP 604). Both scopes are in `~/.claude.json`. So the file in the guide is correct, but the scope name differs. The exam uses the guide.
- **C2. Expansion as the way to keep secrets out.** K2 (GUIDE 291) agrees with CC-MCP 631. But CC-MCP 670 adds that some credential variables read as empty in a remote `url` or `headers`. The guide has no such limit. Weak only for the named credential variables.
- **C3. "Discovered at connection time and available simultaneously" (K3).** The Agent SDK lists only the tools of servers that have connected (SDK-MCP 231). Claude Code by default loads only names at the start and full definitions on demand (CC-MCP 1440, 1487). A server that connects late adds its tools during the turn (CC-MCP 307). A cached server gives its tools before it connects (CC-MCP 272). Condition: Claude Code v2.1.221 or later, and the discovery cache is off by default (CC-MCP 274). So "at connection time" is not exact for Claude Code today. "Available simultaneously" holds. The exam uses the guide.
- **C4. Resources "reduce exploratory tool calls" (K4, S5).** No page read says this. In Claude Code, Claude itself reads resources with tools (`ListMcpResourcesTool`, `ReadMcpResourceTool`, CC-TOOLS 37, 44). Only a user `@` reference attaches a resource with no tool call (CC-MCP 1430). Weak support for the claim.
- **C5. MCP tool against a built-in tool (S3).** No page read says that an agent prefers Grep over a more capable MCP tool. DEF 73 supports detailed descriptions in general. SDK-MCP 635 says only that "Claude can fall back to built-in tools when the server is unavailable", a different cause. Also, CC-MCP 1458: Claude Code truncates each tool description "at 2,048 characters by default". A longer description loses its end. The exam uses the guide.
- **C6. Community servers over custom ones (S4).** The documentation does not say "prefer community servers". It points to reviewed connectors (CC-MCP 28) and warns: "Verify you trust each server before connecting it." (CC-MCP 31). The exam uses the guide.
- **C7. Resources in "agent workflows" on the Claude API.** The MCP connector of the Messages API (beta, CONN 6) supports tools only: "only [tool calls](https://modelcontextprotocol.io/docs/concepts/tools) are currently supported." (CONN 40). For resources, CONN 1192 sends the reader to "the client-side helpers". The guide does not separate these products.
