## 2. The takeaway

**Proposed heading (9 words):** "Plan first when the change is big or unclear"

**Short answer:** In plan mode, Claude reads the code and proposes a plan, and edits wait until you approve it. Use it for large, multi-file or architectural changes, execute a small clear change directly, and let the Explore subagent do verbose discovery so that only a summary comes back.

Support: F1 to F3 (when to plan, K1, K2, S1, S2), F4 to F7 (what plan mode does, K3), F8 to F10 (plan, then implement, S4), F12 to F17 (Explore, K4, S3).

## 9. Conflicts

- **C1. "Direct execution" is not a term of the product.** The guide uses it (GUIDE 382, 389, 1004). No copy of the documentation in `academy/sources/` has the words "direct execution". The documentation says "ask Claude to do it directly" (BP 108), and the modes other than `plan` are `default`, `acceptEdits`, `auto`, `dontAsk` and `bypassPermissions` (PM 17-24). The exam uses the guide term. The page can say that direct execution means "not in plan mode".
- **C2. "Safe" exploration has a condition.** K3 says plan mode "enables safe codebase exploration" (GUIDE 383). The documentation blocks edits "Except in interactive terminal sessions with [bypass permissions available]" (PM 266, 589). Shell commands also run during planning (PM 266, 271-272). The exam uses the guide.
- **C3. Explore or Plan subagent.** K4 and S3 name the Explore subagent. In plan mode, the documentation sends research to a different built-in, the Plan subagent (SA 53, 59). Both are read-only (SA 37, 56). Also, Claude chooses to delegate to Explore (SA 47), and the guide says "Using the Explore subagent" as if the user chooses. A user can name a subagent in a prompt (SA 836). The exam uses the guide.
- **C4. "Multi-phase tasks" (S3).** SA 1006 says to keep work in the main conversation when "Multiple phases share significant context, such as planning, implementation, and testing". This does not contradict S3: the subagent takes only the verbose discovery phase and returns a summary (SA 971).
- **C5. The claim "no plan mode in the build" is an absence.** Decision 0023 line 29 says "The build did not use plan mode". The search of fact 6.5 supports it, but no record can prove the absence (claude-code.md C6.1). The page says "No record shows that the build used plan mode", and that is correct.
