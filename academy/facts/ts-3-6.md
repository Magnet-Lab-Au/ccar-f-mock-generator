## 2. The takeaway

**Proposed heading (9 words):** "In CI, run claude -p with a schema and context"

**Short answer:** In a pipeline, `claude -p` runs once and exits, and `--output-format json` with `--json-schema` gives findings that a script can post as PR comments. CLAUDE.md, the prior findings and the existing tests give the context, and a separate session, not the writer, reviews the code.

Support: F1 to F4 (-p), F5 to F8 (schema output, C2, C3), F9 to F12 (CLAUDE.md, C1), F13 to F15 (independent review), F16 to F18 (prior findings and tests, C5, C6).

## 9. Conflicts

- **C1. CLAUDE.md in CI.** K3 and S5 make CLAUDE.md "the mechanism" for project context to CI-invoked Claude Code (GUIDE 419). The documentation recommends `--bare` for CI, and bare mode skips CLAUDE.md (H 37, 109, 70). Without `--bare`, `-p` loads the same context as an interactive session (H 37), and the GitHub Action and GitLab read CLAUDE.md (GHA 291, GL 360). In bare mode, context comes through flags such as `--append-system-prompt` (H 55). The exam uses the guide.
- **C2. "Enforcing" structured output.** K2 says the flags are "for enforcing structured output" (GUIDE 418). The documentation says the output is validated after the run, with re-prompts, and the run can still end without valid data (CLI 103, SO 9, SO 388, SO 390). Also, `--output-format json` alone does not apply a schema (H 150). The exam uses the guide wording.
- **C3. How inline comments get posted.** S2 builds inline PR comments from `--json-schema` output (GUIDE 425). The GitHub Action posts inline comments through an MCP tool that `--allowedTools` must name (GHA 249, 255), and the managed Code Review posts them itself (CR 33). No documentation page found shows `--json-schema` output that a script posts as inline comments. The guide pattern is valid but not the documented path. The exam uses the guide.
- **C4. The "hang".** S1 and sample question 10 say that `claude` without `-p` waits for interactive input in CI (GUIDE 424, 862). This agent found no documentation sentence that says so. Also, a `-p` run can stay open: H 75, "After Claude finishes its turn and stdin has closed, a `claude -p` run can stay open to wait for background work that Claude started." By default the cap is 10 minutes (H 77). The exam uses the guide.
- **C5. S3 has no direct documentation source.** No page found tells you to put prior findings in the prompt and to report only new issues. The documented products do it in other ways: the Code Review service resolves fixed threads on the next push run (CR 53) and takes a re-review rule in REVIEW.md (CR 194), and the plugin skips PRs with a Claude comment (GHA 257). The claim rests on the guide.
- **C6. S4 has partial support.** CW 216 says Claude examines existing test files "to match the style, frameworks, and assertion patterns", not to avoid duplicate scenarios. The duplicate part rests on the guide.
