## 2. The takeaway

**Proposed heading (9 words):** "A required order needs a code gate, not a prompt"

**Short answer:** When a step must come first, such as identity verification before a refund, code blocks the later tool call until the step is done, because a prompt instruction can fail. When the agent escalates, it gives the human a structured summary, because the human does not see the conversation.

Support: F1, F2, F3, F5 (gate), F4 (a prompt can fail), F12 and GUIDE 178 (handoff, guide only, C3). Sample question 1 (GUIDE 740-750) makes the same claim.

## 7. Code for a popup

SDK-HOOKS 45-91 (Python), exact, without the indent of 2 spaces that the `<CodeGroup>` adds. It blocks a call before it runs. It is not a prerequisite gate (C2).

```python
import asyncio
from claude_agent_sdk import (
    AssistantMessage,
    ClaudeSDKClient,
    ClaudeAgentOptions,
    HookMatcher,
    ResultMessage,
)


# Define a hook callback that receives tool call details
async def protect_env_files(input_data, tool_use_id, context):
    # Extract the file path from the tool's input arguments
    file_path = input_data["tool_input"].get("file_path", "")
    file_name = file_path.split("/")[-1]

    # Block the operation if targeting a .env file
    if file_name == ".env":
        return {
            "hookSpecificOutput": {
                "hookEventName": input_data["hook_event_name"],
                "permissionDecision": "deny",
                "permissionDecisionReason": "Cannot modify .env files",
            }
        }

    # Return empty object to allow the operation
    return {}


async def main():
    options = ClaudeAgentOptions(
        hooks={
            # Register the hook for PreToolUse events
            # The matcher filters to only Write and Edit tool calls
            "PreToolUse": [HookMatcher(matcher="Write|Edit", hooks=[protect_env_files])]
        }
    )

    async with ClaudeSDKClient(options=options) as client:
        await client.query("Create a .env file with the standard local development database configuration")
        async for message in client.receive_response():
            # Filter for assistant and result messages
            if isinstance(message, (AssistantMessage, ResultMessage)):
                print(message)


asyncio.run(main())
```

## 9. Conflicts

- **C1. Overlap with 1.5.** 1.5-K3 (GUIDE 186) and 1.5-S3 (GUIDE 192) repeat 1.4-K1 and 1.4-K2 ("hooks for deterministic guarantees versus relying on prompt instructions for probabilistic compliance"). No disagreement, but the page must not say the same thing twice.
- **C2. "Prerequisite gates" is not a product feature.** GUIDE 170 and 176. The documentation has hooks that check one call (SDK-HOOKS 149, 359-373). It shows no hook that waits for the result of an earlier call. The hook input has a session ID and a tool use ID (SDK-HOOKS 239, 241), so the application can keep the state. That a PreToolUse hook implements the gate of S1 is an inference, not a documentation quote. Weak claim.
- **C3. No documentation for the handoff.** K3 and S3 have only guide sources. CS 160 covers escalation accuracy ("Aim for an escalation accuracy of 95% or higher."), not the content of a handoff. Weak claim for any product fact about handoffs.
- **C4. "In parallel using shared context" (S2).** GUIDE 177. If the items go to subagents, they do not share context: SDK-SUB 178 says "The only content you pass from parent to subagent is the Agent tool's prompt string". If one agent investigates with parallel tool calls (PAR 11), the context is shared. The guide does not say which. Decision 0077, line 23, records a mock 5 overlap of 1.4-S2 with the Task tool question M5-S05. The exam uses the guide.
- **C5. "Non-zero failure rate" (K2).** The documentation gives no failure rate for instructions. MEM 24 says only "context, not enforced configuration" and "more consistently". The documentation supports the idea but not the words. Weak claim.
- **C6. The build once overstated 1.4-K2.** `docs/decisions/0038-a-simple-control-for-mock-1-written-as-code-with-tests.md` 46: "A correction of decision 0037, Reason, item 8. The sentence on point 1.4-K2 is too strong." Enforcement by code is 1.4-K1, not 1.4-K2. A page must keep K1 (code enforces) and K2 (a prompt can fail) apart. Decision 0044, line 43, also says that the build uses "only its general idea".
- **C7. Step 2 points.** Decision 0029, line 159, lists 1.4-K1 and 1.4-K2 for step 2. The table of the build guide for step 2 (line 52) shows only 1.4-K2.

Number of conflicts: 7 (C4, C6 and C7 are disagreements of sources, C1 is an overlap, C2, C3 and C5 are weak claims).
