## 2. The takeaway

**Proposed heading (8 words):** "Name what to report, not how careful to be"

**Short answer:** A review prompt gets precise when it names the categories to report and to skip, and gives a code example for each severity level. "Be conservative" does not make it precise, and one noisy category makes developers ignore the good findings, so switch that category off while you fix its prompt.

Support: F1 to F4 (explicit criteria), F5 and F6 (vague and confidence instructions, C1, C2), F7 and F8 (trust, C4), F9 and F10 (report and skip, C3), F11 and F12 (severity, C5). S2 rests on the guide (C3).

## 9. Conflicts

- **C1. Confidence as a filter.** K2 and S1 reject "only report high-confidence findings" and "confidence-based filtering" (GUIDE 440, 445). CR 343 says that `/code-review` at `low` effort "reports the findings it's most confident in, so you see fewer false positives". CR 188 suggests for some paths: "in `scripts/`, only report if near-certain and severe." The exam uses the guide.
- **C2. Why "be conservative" fails.** K2 says it fails "to improve precision" (GUIDE 440). O5 16 says the model "may follow that instruction literally and report less", which is a loss of recall, and it advises to "report everything and filter in a separate pass". Both reject the instruction, for different reasons. Condition of O5: Claude Opus 5. The exam uses the guide.
- **C3. S2 has no documentation source.** CR 188 lists "finding categories where Claude should post no findings", but no page says "temporarily" or "restore developer trust". The claim rests on the guide.
- **C4. K3 has no documentation source.** No page says that a high false positive category undermines confidence in accurate categories. The nearest is CR 51 (findings rated "wrong or noisy") and CR 192 (a false positive costs "the author a round trip"). The claim rests on the guide.
- **C5. Code examples for each severity level.** S3 asks for "concrete code examples for each severity level" (GUIDE 447). CR 184 and CR 205-211 define the levels by classes of finding in prose, with no code example. Examples in general are 4.2 (PBP 83: "Examples are one of the most reliable ways to steer Claude's output format, tone, and structure."). The exam uses the guide.
