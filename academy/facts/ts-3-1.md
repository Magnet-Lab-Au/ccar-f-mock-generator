## 2. The takeaway

**Proposed heading (10 words):** "Team instructions live in the project CLAUDE.md, split into files"

**Short answer:** Claude Code joins the CLAUDE.md files of the user, the project and its subdirectories, and only the project files reach teammates through git. Imports and `.claude/rules/` split a long file into topic files, and `/memory` and `/context` show the files.

## 9. Conflicts

- **C1. Three levels or more.** K1 (GUIDE 329) names user, project and directory. The documentation has four scopes in its table: managed policy, user, project and local (MEM 59-62), plus subdirectory files (MEM 146) and user rules in `~/.claude/rules/` (MEM 268). The guide is not complete. The exam uses the guide.
- **C2. The directory level loads late.** The guide lists subdirectory files as a level (GUIDE 329). The documentation loads them only when Claude reads, writes or edits a file in that subdirectory (MEM 146). They do not show under "Memory files" in `/context` (MEM 583, DBG 30).
- **C3. Which command shows the loaded files.** S4 says `/memory` verifies "which memory files are loaded" (GUIDE 342). The documentation says `/memory` lists file locations, also of files that do not exist yet (MEM 566). For the loaded files it names `/context` (MEM 566, 582, DBG 15). CMD 111 describes `/memory` as a command to edit the files and to switch auto memory. One exception: MEM 605 uses `/memory` to check if Claude read an `AGENTS.md`. G046 and fact 1.12 of `academy/facts/claude-code.md` repeat the guide wording. That claim is weak. The exam uses the guide.
- **C4. The name "@import".** K3 and S2 say "@import syntax" (GUIDE 331, 337). The documentation names "`@path/to/import` syntax" (MEM 102). There is no keyword `import`. The build writes `@WORKING-RULES.md` (`CLAUDE.md` 9). Small.
- **C5. "selectively include" and context.** S2 suggests that a package takes only the files that it needs (GUIDE 337). Each import loads at launch with its CLAUDE.md (MEM 102). Imports do not reduce context (MEM 88, 617). The saving comes only because a package CLAUDE.md loads when Claude starts in that package or works with its files (LCB 99, MEM 146).
- **C6. Rules as "an alternative to a monolithic CLAUDE.md".** K4 and S3 (GUIDE 332, 338) agree with MEM 168. But a rule with no `paths` loads at launch (MEM 188), so the split saves no context. Only `paths` makes a rule load on demand (MEM 194, task statement 3.3).
- **C7. "user-level settings".** K2 (GUIDE 330) says "settings" for instructions in `~/.claude/CLAUDE.md`. In Claude Code, "settings" are the `settings.json` files (SDKF 79 lists "User `settings.json`" apart from "user CLAUDE.md"). Small.
