## 2. The takeaway

**Proposed heading (9 words):** "Errors must say what failed and whether retry helps"

**Short answer:** Mark a failed tool call with the error flag, and say the category, whether a new try can help, and what went wrong, so the agent can retry, fix its input, explain or escalate. A subagent repairs transient failures itself, and an empty result of a query that succeeded is not an error.

Support: F1 to F4 (the flag), F6 and F7 (an instructive message lets Claude recover), F8 (Claude retries a call with bad input), F12 to F14 (the guide fields and categories), F15 and F16 (partial work goes back to the caller), GUIDE 264 (empty result). The field names and the categories are claims of the guide only (conflict C1).

## 5. Beyond the exam

1. **Claude Code cuts long error text.** CC-MCP 1291: "Error text longer than about 11,000 characters keeps only its first 5,000 and last 5,000 characters, with a marker between them that says how many characters were removed". Condition: Claude Code as the MCP client. Put the category and the retry advice at the start of the text. The guide does not say this.
2. **A Python SDK tool cannot return separate structured fields.** SDK-TOOLS 652: "The Python `@tool` decorator forwards only `content` and `is_error` from the handler's return dict. To return `structuredContent` from Python, run a [standalone MCP server](/docs/en/agent-sdk/mcp) instead of an in-process SDK server." Condition: Agent SDK, Python, in-process server. So the metadata of S1 must go into the text of `content` there. Marked: the guide (GUIDE 261) does not say where the metadata goes (C1).
3. **An uncaught exception does not stop the loop, but Claude sees only the raw message.** SDK-TOOLS 400: "A handler error doesn't stop the agent loop. The SDK's in-process MCP server catches uncaught exceptions and returns them as error results". SDK-TOOLS 404: "The MCP server converts it to an error result carrying the raw exception message." Condition: Agent SDK in-process server. A raw exception is close to the generic error of K3. The guide does not name this case.

## 9. Conflicts

- **C1. The field names are the guide's, not a product's.** No documentation page names `errorCategory`, `isRetryable` or `retriable`. A grep of all copies in `academy/sources/` finds none. The documentation flag is `is_error` (HANDLE 58) or `isError` (SDK-TOOLS 38), and the advice is an instructive text message (HANDLE 224). The exam uses the guide names.
- **C2. Two spellings in the guide.** S1 says "isRetryable" (GUIDE 261), S2 says "retriable" (GUIDE 262). K4 says "retryable" (GUIDE 257). The exam uses the guide. Tab 1 must quote each one as the guide writes it.
- **C3. Three categories or four.** K2 names four types, with business errors (GUIDE 252). S1 lists errorCategory as "transient/validation/permission" (GUIDE 261), without business. S2 gives business errors their own flag (GUIDE 262).
- **C4. Two names for one flag.** The guide says "isError" (GUIDE 251, 1000), as in MCP and the TypeScript SDK (SDK-TOOLS 405). The Claude API, the Python SDK and the MCP connector use `is_error` (HANDLE 58, SDK-TOOLS 405, CONN 517).
- **C5. "Validation" and "retryable".** The guide groups validation errors as one category (GUIDE 252). The documentation says Claude retries a call with bad input "with corrections" (HANDLE 247). So a validation error is retryable only with new input, not as the same call. The guide does not say this. Weak point for K4.
- **C6. No action for permission errors.** The guide names permission errors (GUIDE 252, 261) but gives no recovery for them. The documentation has no statement on permission errors of a tool result. Not found.
- **C7. Weak documentation support for S3 and S4.** No documentation page says "recover locally, then pass up only what you cannot fix" for tool errors. F15 and F16 are about API errors of Claude Code subagents. F17 is a prompt example of Managed Agents, beta. No page compares an access failure with a valid empty result. HANDLE 141-151 only shows an empty `tool_result`. The exam uses the guide.
- **C8. 2.2 and 5.3 overlap.** 2.2-S3 repeats 5.3-S3 (GUIDE 593). 2.2-S4 repeats 5.3-K2 and 5.3-S2 (GUIDE 585, 592). 2.2-K3 is close to 5.3-K3 (GUIDE 586). Point groups G028 to G030 join them. Sample question 8 fits both.
- **C9. "MCP" in the title.** The guide title says "for MCP tools" (GUIDE 247). The documentation gives the same pattern for all client tools of the Claude API (HANDLE 205). The pattern is not special to MCP.
