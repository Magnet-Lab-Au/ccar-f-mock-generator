## 2. The takeaway

**Proposed heading (9 words):** "Resume valid context, fork to compare, restart when stale"

**Short answer:** Resume a named session when its earlier tool results are still true, and tell it which files changed. Fork a session to try two approaches from one analysis, and start a new session with a structured summary when the old tool results are stale.

## 5. Beyond the exam

1. **A fork shares the files.** SDK-SESS 293: "Forking branches the conversation history, not the filesystem. If a forked agent edits files, those changes are real and visible to any session working in the same directory. To branch and revert file changes, use [file checkpointing](/docs/en/agent-sdk/file-checkpointing)." So two forks that try two refactors in one folder change the same files. Marked: the guide says "independent branches" (GUIDE 215) and does not say this (C5).
2. **Resume replays old hook output.** HOOKS-REF 1096: "when you resume with `--continue` or `--resume`, Claude Code replays the saved text rather than re-running the hook for past turns, so values like timestamps or commit SHAs become stale. `SessionStart` hooks run again on resume with `source` set to `\"resume\"`, or `\"fork\"` if you added `--fork-session`, so they can refresh their context." A SessionStart hook is one way to give a resumed session the new state (K3, S4) by code. The guide does not name it.
3. **The product offers a middle path: resume from a summary.** CC-SESS 99 offers it when a session "has been inactive for more than about an hour and is over 100,000 tokens". CC-SESS 103: "**Resume from summary**: runs [`/compact`](/docs/en/context-window#what-survives-compaction) immediately. Later requests carry the summary instead of the full history." CC-SESS 107: "whatever the summary leaves out is no longer in Claude's context." Marked: the guide gives two choices (GUIDE 223). The product has this third one. A compacted summary still comes from the old, possibly stale results.
