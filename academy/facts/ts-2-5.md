## 2. The takeaway

**Proposed heading (10 words):** "Grep finds content, Glob finds files, Edit needs unique text"

**Short answer:** Search first: Glob finds files by name, Grep finds text inside files, and Read then follows only the files that matter. Edit changes a part of a file and needs text that occurs once. When it does not, the guide answers with Read and then Write of the whole file.

Support: F1 to F4 (Grep), F5 to F7 (Glob), F8 to F10 (Read, Write, Edit), F11 to F13 (the unique match and its fallback, C2), F14 to F16 (search first, read less). The platform condition is in F17 and C1.

## 5. Beyond the exam

1. **On macOS, Linux and WSL, Grep and Glob are not tools by default.** TR 304: "On macOS, Linux, and WSL, Claude Code leaves Glob and [Grep](#grep-tool-behavior) out of the default tool set, and Claude searches with `find` and `grep` through the Bash tool instead." The searches then "reach your hooks and permission rules as `Bash` calls" (TR 304). A subagent that lists Grep or Glob and leaves out Bash gets them back (TR 310). Condition: the platform. On Windows, Glob is in the default tool set: "On Windows, it's part of the default tool set." (TR 304). Marked: the guide treats Grep and Glob as tools to select on every platform (C1).
2. **Read does not always load the full file.** TR 516: "By default one call returns at most 25,000 tokens, or the value you set in [`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS`](/docs/en/env-vars), and refuses a whole file over 256 KB, so Claude reads a larger file in pages with `offset` and `limit`." A file that Claude read only in part needs a full read before a Write: "files Claude has read only partially with a [`PARTIAL view` notice](#large-files), require the read on every model" (TR 676). Condition: the default limits. Claude Code v2.1.296 or later can read a whole file with `allow_large: true` (TR 516). Marked: K3 and S3 say "full file" with no limit (C3).
3. **To find callers, a language server can replace text search.** TR 351: "Find all references to a symbol". Condition: TR 358: "Claude Code keeps the tool inactive until you install a [code intelligence plugin](/docs/en/plugins/code-intelligence) for your language." The guide does not name the LSP tool. S5 uses Grep for the same goal.

## 9. Conflicts

- **C1. Grep and Glob as tools.** The title, K1, K2, S1, S2 and S4 treat Grep and Glob as tools to select (GUIDE 303-320). TR 34, 35 and 304: on macOS, Linux and WSL they are "Absent by default", and Claude uses `find` and `grep` through Bash. The exam uses the guide. A second, smaller conflict: LOOP 158 lists `Glob` and `Grep` in the Agent SDK with no platform condition. TR 308 says that a user gets them back by naming them "in the equivalent [Agent SDK](/docs/en/agent-sdk/overview) options", which suggests that the SDK default also leaves them out. Not checked in an SDK page.
- **C2. The fallback for a non-unique Edit.** K4 and S3: Read + Write (GUIDE 313, 319). TR 256: "a longer string with enough surrounding context" or `replace_all: true`. The documentation does not name Read + Write as the fallback. The exam uses the guide. A reader must know both: Write replaces the whole file (TR 670), so the guide's fallback is the heavier change.
- **C3. "Full file" (K3, S3).** TR 516 and 520: over 25,000 tokens, Read gives the first page with a `PARTIAL view` notice, and it refuses a file over 256 KB. So "Read to load full file contents" (GUIDE 319) holds only for files under the limits, or with `allow_large: true` on Claude Code v2.1.296 or later. Weak for large files.
- **C4. Scenario 4 leaves out Edit.** GUIDE 91 lists "(Read, Write, Bash, Grep, Glob)". The title of 2.5 (GUIDE 303) and GUIDE 1010 include Edit. Small. It does not change an answer.
