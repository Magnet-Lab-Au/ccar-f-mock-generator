Exam guide breakdown · Domain 1 · Task statement 1.1 Behind the mocks 1.1 ↓

The loop runs while Claude asks for tools

“Design and implement agentic loops for autonomous task execution”

Your code sends a request to Claude and checks stop_reason. "tool_use": run the tool and send the result back. "end_turn": stop.

Overview · 30 seconds

Explanation

3 minutes

Who decides. The guide makes a distinction. In model-driven decision-making, Claude reasons about which tool to call next, from the context. The other side is a decision tree or a sequence of tools that somebody sets up in advance. The memory of the loop: your code adds each tool result to the conversation history, so that Claude can use the new information when it decides the next action.

The exam tests

The guide lists this topic as tested: “Agentic loop implementation: control flow based on stop_reason, tool result handling, loop termination conditions”. Under the Claude API, its list of technologies names “stop_reason values ("tool_use", "end_turn")”.

The guide’s own text

K = Knowledge ofS = Skills in1.1-K2 = domain 1 · task statement 1 · point 2. The labels are ours. The guide has no labels.

Knowledge of:

  • 1.1-K1 The agentic loop lifecycle: sending requests to Claude, inspecting stop_reason ("tool_use" vs "end_turn"), executing requested tools, and returning results for the next iteration
  • 1.1-K2 How tool results are appended to conversation history so the model can reason about the next action
  • 1.1-K3 The distinction between model-driven decision-making (Claude reasons about which tool to call next based on context) and pre-configured decision trees or tool sequences

Skills in:

  • 1.1-S1 Implementing agentic loop control flow that continues when stop_reason is "tool_use" and terminates when stop_reason is "end_turn"
  • 1.1-S2 Adding tool results to conversation context between iterations so the model can incorporate new information into its reasoning
  • 1.1-S3 Avoiding anti-patterns such as parsing natural language signals to determine loop termination, setting arbitrary iteration caps as the primary stopping mechanism, or checking for assistant text content as a completion indicator

Behind the mocks · 1.1 Agentic loops Source: the pipeline Task statement 1.1 ↑

A pass stops the loop. The limits are only guards.

The mock builder is not an agentic loop. Code and the owner decide each next step. No model decides it. The builder has one small loop: a question that fails a check goes back to the writer.

Overview · 30 seconds

The story

3 minutes

A question that fails the check by code or the check by a model goes back to the writer with the exact findings. A limit of 3 tries and a limit of two results “cannot decide” are only guards. This follows 1.1-S3: an arbitrary limit of iterations must not be the main way to stop. The guide wrote that point for agent loops. The builder uses the same idea for a loop of retries.
