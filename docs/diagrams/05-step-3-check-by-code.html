Step 3: code checks each question against 12 exact rules

This diagram shows step 3. The step is built, and it ran in the test of 7 October 2026. Before a model looks at a question, code checks the rules that have one exact answer. Put the pointer on a box, or select it with the keyboard, to see the detail and an example. A click keeps the detail open.

2Code saves the verdict
Code checks 12 rulesCode

Each rule has one exact answer.

A1
The form is complete

Each option: a text, a mark, a reason.

A2
The number of options

4 or 5, as the slot says.

A3
The number of correct options

1 or 2, as the slot says.

A4
No equal options

No two options have the same text.

A5
No letters in the text

No "Option B", no "all of the above".

A6
The length

Question 25 to 110 words. Option 5 to 45.

A7
Correct option not much longer

At most 1.3 times the wrong options.

A8
A question mark at the end

The question ends with "?".

A9
2 to 5 sentences

In the text of the question.

A10
Each option is one sentence

No sentence end inside an option.

A11
Not a negative question

No "NOT" or "EXCEPT" in capital letters.

A12
The longest option

Most slots: a wrong option is the longest.

The question record

The question and its options, from step 2.

The slot

What the question must be, from the plan.

PassUsual

No rule fails. Step 4 checks the question next.

Fail

A rule fails. The question goes back to the writer with the findings.

The verdict recordFile

One new file for each check: the question, the verdict and the findings.

A finding is exactCode

It names the rule and the detail, so the writer knows what to change.

An error is not a pass

If code cannot read the question, it reports an error.
