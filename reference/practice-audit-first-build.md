# Practice audit: the exam guide against the old process

Date: 2 October 2026. Scope: the first build of the five mocks (August 2026) and the review for the portal (September 2026).

## 1. The question

The exam guide lists 240 Knowledge and Skills points in 30 task statements. For each point: was the practice applied when the mocks were built? If not, could it have been applied?

## 2. Method

1. Code listed the 240 points with an ID.
2. Pass 1: five agents, one for each domain, gave each point a code with evidence from the files.
3. Code checked the quotes of pass 1: 462 of 463 quoted strings exist in the files, and the last one exists in a file on the owner's computer.
4. Pass 2: five new agents, one for each domain, checked each row. They gave one code for each phase and rated each gap.
5. One more agent tried to disprove the 49 rows that pass 1 coded "not applied", "design only" or "instruction only". It moved 9 rows to "applied in part".
6. The coordinator decided 12 rows where the agents did not agree (column "decided by" in the JSON file).

Limits:

- The planned second check of the 52 rows with a weak fit or no fit did not run. For these rows the result has one check, not two.
- The August prompts and the generator code are lost. For August, "applied" often rests on the build log, which is the coordinator's own account.
- The agents had no enforced tool limits. A comparison of the owner's folder before and after the first agent run found no changed file.
- The coordinator did not read all 11 "Applied" rows again by hand.

Phases: P1 = prepare the sources (14 August). P2 = generate the mocks (25 to 30 August). P3 = review for the portal (28 to 29 September).

Phase codes: A = a record shows use. I = a brief asked for it and nothing enforced it. D = the design planned it and no record shows that it ran. C = it fits and no record or plan shows it. - = it has no object in that phase.

## 5. New findings of this audit (not in the list F1 to F12)

The coordinator computed each of these from the files.

1. The 58 warning lines of August are in 0 of the five portal files. The build script reads the field `flagged`. The records hold `generation_flagged` (Mocks 2, 4, 5) or no flag field (Mocks 1 and 3). No record shows a decision to drop the warnings.
2. The August verifier saw each banked stem cut at about 120 characters. 22 verifier notes say so, from run r2 to Mock 5. 16 of the 23 needs-review reasons are this. Nobody supplied the full text.
3. Mock 2 has no question on task statement 1.6 (three were generated, all three were rejected, none was retried). Mock 3 has no question on 1.5.
4. `guide_bullet` is exact guide text in 15 of 342 bank records (at most 38 by the loosest test). The design calls it "The exact bullet". No code compared it with the guide.
5. For 23 questions the August paper has a rewritten option text (28 texts) and the bank holds the old text. For 7 more questions the order of the options differs. So the bank is not the source of the papers.
6. In the first September review of Mocks 2, 4 and 5, 97 of 180 questions failed (54%). The rate is 0% to 100% by task statement and 33% to 83% by slice. Nobody split the result.
7. Reviewer confidence was "high" in 481 of 510 judgments. 7 judgments use "medium", which the rubric does not allow.
8. The two owner rulings came on 29 September, after the build. 32 and 24 questions of Mocks 2, 4 and 5 then failed on them.
9. The later review packets hold the notes of the editor (`editor_changes` in 62 of 120 and 97 of 180 items). So the reviewer did not judge without the writer's reasoning.
10. Summary files differ from their data. The coverage matrix says 8, 12 and 10; its rows count 6, 13 and 11.
11. `08 Exam Guide (full copy).md` has 31,581 bytes. The full guide has 88,139 bytes.
12. Two plugin files of 2 and 3 September show that a saved skill with settings was possible in the product before Phase 3. One of them tests whether an agent definition with a tool list loads. No record shows the result.
